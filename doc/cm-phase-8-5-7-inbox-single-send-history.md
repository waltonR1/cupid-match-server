# Phase 8.5.7：Inbox 后台单发记录

## 1. 目标

- 为后台定向通知补齐“发送后可回看”的运营能力。
- 让后台能够查看单发历史、发送对象、模板或自定义正文、关联业务对象和发送时间。
- 保持当前 C 端收件箱模型不变，不重做线程归档方式。

## 2. 非目标

- 不调整 C 端消息中心展示结构。
- 不修改现有通知模板、多语言和投递逻辑。
- 不在本阶段实现撤回、重发、导出和完整统一发送中心。
- 不改变“同业务对象复用同一系统线程”的当前收件箱模型。

## 3. 范围

本阶段只补“后台单发记录可追溯性”，不扩展到后台群发记录之外的统一消息运营中心。

## 4. 数据结构

建议新增 `cm_inbox_single_dispatches`，用于记录每次单发任务：

- `id`
- `staff_user_id`
- `user_id`
- `message_id`
- `mode`
- `template_code`
- `locale`
- `subject_type`
- `subject_id`
- `payload_json`
- `status`
- `error_message`
- `created_at`
- `updated_at`

说明：

- `message_id` 关联实际写入 `cm_inbox_messages` 的消息。
- `payload_json` 保留单发时的模板变量或三语自定义正文快照。
- `status` 用于区分 `success / failure`。

## 5. 后端改动

- 后台单发执行时，先创建单发记录，再调用现有通知写入链路。
- 发送成功时回写 `message_id` 和 `status=success`。
- 发送失败时记录 `status=failure` 和 `error_message`。
- 新增后台查询接口：
  - `GET /cupid/inbox/single/list`
  - `GET /cupid/inbox/single/{id}`

## 6. 后台页面改动

- 在现有通知发送页中增加“最近单发记录”区域，或在群发记录旁提供标签切换。
- 列表展示发送时间、发送人、目标用户、发送模式、模板或摘要、关联业务对象、发送状态。
- 支持查看详情；详情展示最终正文、模板变量或自定义正文快照、关联对象和失败原因。
- 当前发送表单、模板选择、预览和发送流程保持不变。

## 7. 验收标准

1. 后台执行一次单发后，可在记录列表中看到该记录。
2. 列表能正确展示目标用户、发送模式、关联业务对象和发送状态。
3. 点开详情后，可查看最终正文和失败原因。
4. 不影响当前单发、群发、模板预览和 C 端消息展示。
5. 后台重启后历史记录仍可查询。

## 8. 阶段结论

`8.5` 完成 Inbox 通知发送与 C 端承接。  
`8.5.7` 用于补齐后台单发记录与可追溯性，使后台定向通知具备基础运营闭环。
